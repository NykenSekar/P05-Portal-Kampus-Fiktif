Laporan Audit Keamanan OWASP Top 10 (Sengaja Ditanam)

Halaman ini mendokumentasikan 4 jenis kerentanan yang sengaja diimplementasikan dalam portal ini untuk kebutuhan tugas praktikum M5.

1. SQL Injection (Bypass Login)

Lokasi: Form Login Halaman Utama

Mekanisme Celah: Query login menerima karakter kutip satu tanpa prepared statement.

Payload: admin' OR '1'='1 --

2. Stored Cross-Site Scripting (XSS)

Lokasi: Fitur Forum Diskusi Akademik

Mekanisme Celah: Pesan disimpan di localStorage dan ditampilkan via innerHTML tanpa sanitasi.

Payload: <img src=x onerror=alert('XSS Berhasil!')>

3. IDOR / Kontrol Akses Lemah

Lokasi: Fitur Kartu Hasil Studi (KHS) Mahasiswa

Mekanisme Celah: Nilai ditampilkan berdasarkan objek ID tanpa validasi hak kepemilikan sesi.

Eksploitasi: Ganti ID ke M002 / M003 untuk melihat nilai mahasiswa lain

4. Validasi Berkas Lemah (Unrestricted Upload)

Lokasi: Fitur Unggah Tugas Mahasiswa

Mekanisme Celah: Menerima sembarang ekstensi berkas (.php, .exe, .sh) tanpa validasi MIME type.

Eksploitasi: Upload file webshell.php atau exploit.html

🛡️ Panduan Audit Kerentanan (Untuk Penilai Dosen)

Proyek portal kampus fiktif ini dibuat untuk memenuhi tugas M5 Keamanan Sistem Informasi dengan 4 kerentanan sengaja yang dapat langsung diuji:

☑️ Stored XSS (Forum Diskusi)

Komentar forum disimpan dan dirender dengan innerHTML mentah.

☑️ Validasi Berkas Lemah (Upload Tugas)

Unggah berkas tanpa whitelist ekstensi, menerima .php, .html, dan skrip eksekutabel.

☑️ IDOR / Kontrol Akses Lemah (KHS Nilai)

Mengakses dan melihat transkrip nilai mahasiswa lain cukup dengan mengganti ID mahasiswa.

☑️ SQL Injection (Form Login)

Bypass autentikasi menggunakan payload ' OR '1'='1 --.
